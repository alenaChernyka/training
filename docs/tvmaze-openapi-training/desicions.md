# Принятые решения

## Переиспользование компонентов

**Решение:** выносить схему или параметр в `components` только при повторном использовании.

**Причина:** единичные элементы оставлять непосредственно в эндпоинте, а повторяющиеся — выносить в переиспользуемые компоненты и подключать через `$ref`. Это позволяет избежать преждевременного усложнения спецификации и уменьшить дублирование.

## Редирект в `/lookup/shows`

**Решение:** описывать отдельно ответы `301` и `200`.

**Причина:** API возвращает `301` с заголовком `Location`, но большинство клиентов автоматически следуют редиректу и показывают конечный ответ `200`. В спецификации отражены оба варианта поведения.

## Параметр `specials`: тип `string`

**Решение:** описать параметр `specials` с типом `string`.

**Причина:** документация TVmaze показывает значение `1`, но тестирование API показало, что параметр включает specials при любом непустом значении, а `0` и пустое значение их не включают. Поэтому `boolean` и `integer` не отражают фактическое поведение API. В качестве рекомендуемого значения используется `1`.
